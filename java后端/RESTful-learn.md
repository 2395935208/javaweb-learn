# RRESTful的概念
RESTful不是Spring提供的某个类，也不是必须完全遵守的法律。
它是一种接口设计风格，目标是让接口：
- 路径含义清楚
- 请求方法合理
- 命名保持统一
- 前端容易理解
- 后期容易维护
实际项目可以根据业务适当调整，但同一个项目要保持一致。
## HTTP方法
HTTP方法表示对资源做什么
常见的有：
GET    查询
POST   新增
PUT    完整更新
PATCH  部分更新
DELETE 删除
## 路径
路径表示操作哪个资源
/users/3       → 定位用户3
/users?age=18  → 筛选用户集合
/users/1/orders → 用户1的订单
## 接口的完整身份
HTTP方法 + 路径
# 请求参数和请求体
@PathVariable → Controller读取路径中的{变量}
@RequestParam → Controller读取?后面的查询参数
@RequestBody → Controller把JSON转换成Java对象
@Param → Mapper给XML参数命名
# 状态码和幂等性
200 → 请求成功，并返回数据
201 → 成功创建资源
204 → 成功，但不返回响应体
400 → 请求参数、格式或类型错误
401 → 没有有效身份
403 → 身份已确认，但没有权限
404 → 请求的资源不存在
409 → 请求与当前数据状态冲突
500 → 未处理的服务器内部异常
## PUT与PATCH的区别
PUT   → 通常完整更新资源
PATCH → 通常只更新部分字段
## 幂等性
同一个请求执行一次或多次，资源的最终状态相同，就具有幂等性。

GET    → 幂等
PUT    → 通常幂等
DELETE → 幂等
POST   → 通常不幂等
PATCH  → 是否幂等取决于具体操作

DELETE第一次可能返回204，第二次可能返回404，但最终状态都是资源不存在，因此仍然具有幂等性。
